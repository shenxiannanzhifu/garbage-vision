# 代码导览与答辩准备

## 从入口看数据流

`启动项目.cmd → scripts/start.ps1 → app.py`。页面通过 images.decode_image 读取实际文件格式、校正方向、合成透明背景，返回 RGB 原图和统一 PNG 哈希。local.infer_local 与 api.infer_api 各自接收这个输入，不交换预测。schema.py 规范字段，exports.py 负责下载，evaluation.py 只对比图片级四分类集合。

本地链路：SAM2.1 自动分割 → 区域外接框与掩膜 → 原图裁剪 → CLIP 图像向量和固定文本向量比较 → 背景过滤/跨类别差值/未知 → 局部碎片与重叠过滤 → 四分类及标注图。SAM 的权重、CLIP 模型和文本向量缓存，图像推理仍每次真实执行，锁防止并发图片污染内部缓存。

API 链路：版本化中文说明+规则+同一张图片 → HTTPS Chat Completions → 严格 JSON 验证 → 同一结果结构。图像独立发送，没有把本地预测作为上下文；不要求大模型虚构框或概率。当前真实评估关闭自动重试；网络失败保留为失败，不能把历史回放当成新请求。

## 学习知识与实际使用的区别

**Transformer。** token 是模型的输入单位，文本通常切成子词，视觉输入通常切为图像块。embedding 把输入映射到向量；位置编码补充顺序或空间位置。attention 通过 Query/Key 的相似关系选择 Value 的信息，自注意力发生在同一序列内部。编码器擅长产生表示，解码器可逐 token 生成输出。本项目 CLIP 使用图像/文本编码器计算表示，图像理解 API 在远端处理多模态上下文；没有从零实现 Transformer，也不能声称已查看闭源模型内部结构。

**OpenCV。** `cv2.imread` 默认 BGR，Pillow 图像通常 RGB；混用会把红蓝通道反转。缩放改变像素坐标，裁剪需要保存偏移，画框必须映射回原图。本项目直接上传解码和中文绘图使用 Pillow；OpenCV 是 Ultralytics 视觉依赖的一部分，不把“安装了 OpenCV”等同于直接写过视频读取管线。摄像头/视频流不在本项目范围。

**YOLO。** 通常直接预测类别、置信度和边界框；框坐标可能是中心点宽高或 XYXY，要看接口定义。NMS 去掉高度重叠的重复框。通用 COCO 类别不覆盖全部垃圾。本项目真实评估过 YOLO-World 和 YOLOE 候选，覆盖不足而未选为最终主路径；没有把 SAM 的分割质量冒充 YOLO 检测概率。

**SAM。** 提示分割可接收点/框；自动模式采样点网格产生许多掩膜。SAM 通常回答“哪里是一个区域”，不直接回答“这是哪类垃圾”。因此加入 CLIP 区域分类；外接框不等于完整物品实例，瓶盖等部件可能另成掩膜。当前修复只抑制位于较高分已知物体内部的低分未知碎片，并保留审计候选，不能保证实例计数。

**大模型应用。** API 是远端服务协议，SDK/HTTP 库是发送它的工具。模型名称、地域、端点和密钥必须匹配。任务说明、规则及图片构成上下文，JSON 必须校验枚举和必填字段。解释只是模型输出，不能当作真值。没有联网调用或只有模拟响应时不能宣称 API 已接入。

## 常见追问

1. 为什么不用检测 mAP 比较 API？API 没有真实框输出；虽然定位训练数据有框真值，但两方案共同评估的是每图四分类出现集合，不能把二值定位mAP当成API分类分数。
2. 为什么未知不能都算其他垃圾？其他垃圾是有定义的实际类别，未知是信息不足状态；混用会掩盖模型缺口。
3. 为什么不用测试集调阈值？会让测试参与开发并高估泛化，必须新建独立数据才可再次声称未见评估。
4. 训练是否有效？已经做过分类层与定位器的真实训练。前者测试退化，后者局部改善但未通过全部升级条件；训练完成不保证泛化提高，详见下面的当前结论。
5. 本地/远端哪种更快？看实测拆分：本地首次加载另计，API 时间含网络；单张成功不能推断总体优劣。
6. 怎么定位瓶盖误报？检查真实 SAM 掩膜、CLIP 分数差、框坐标和原图，发现部件候选；用真实掩膜包含条件减少重复，保留原始候选审计，再跑全部开发图。
7. 免费额度代表无需预算吗？额度可能到期或不适用，只有控制台可核实；调用次数仍限制，返回 usage 与实付费用分开。
8. 怎样理解代码而非背答案？从 decode_image 追到一张图片的 image_id，找本地结果与 API 结果，修改一个开发阈值并观察变化，运行对应测试。



## 当前训练与收尾结论（2026-10-20）

项目已经做过真实监督训练：v0.6训练CLIP分类层，测试20/25→18/25，拒绝升级；v0.7训练YOLOv8n二值物品定位，707图/2221框/37轮，框提示SAM后继续用CLIP四分类。检测mAP只衡量物品框，不能替代分类集合准确率。

v0.8的 `garbage_vision/recall.py` 是实验补漏逻辑，不是重新训练权重：当检测器没有确定类别的定位区域时，加入有真实SAM掩膜且类别差值足够的候选。原图哈希必须一致，未知、整图无框输出不能伪装成区域。固定规则只在开发图选择；随后历史回归和4张真实GPU重跑保留所有输出。默认 `app.py → local.py` 没有调用补漏候选。

需要能解释：整体完全匹配数上升，为什么还可能漏掉某类？因为减少误报和增加漏检可以同时发生。为什么不直接换候选？因为类别召回的回归条件未全过，也没有新的独立测试支持。为什么API成功子集和整体分数不同？前者排除了通信失败，不能代表实际使用成功率。当前只完成有界实验收尾，不声称以后无法优化。
