## 录制顺序（服务器通过后使用）

1. 展示仓库三阶段入口与已部署提交号。说明沿用二阶段模型，本阶段新增接口、任务记录和容器服务。
2. 展示服务器终端的系统与 `docker compose ps`。仅展示不含密钥的命令和状态，不能录制 `.env` 内容。
3. 展示停止与 `docker compose up -d --wait` 启动，说明数据存在挂载目录；等待 API 健康和网页可用。
4. 在网页“新建任务”选择已确认的简单开发图，创建任务，展示等待和完成后的本地结果。说明相似度不是准确率，已有错分不回避。
5. 展示本阶段获授权且真实执行的同图双侧结果、时间、同图标识与导出。调用失败如实展示，不用历史回放冒充刚执行；避免为录视频重复消耗次数。
6. 切换“任务历史”，选择另一条记录，下载 JSON；刷新后历史仍可读取。展示持久化/备份恢复证据。
7. 简述单 worker、重启不自动重发、受控访问及当前模型局限，补充本人真实感悟。

最终访问地址与服务器终端的一条完整 SSH 命令将在资源确定后补上；目前不提供未替换的假地址。本人可用 Windows 已有录屏工具，无固定时长。录完核对画面、声音、密钥遮挡和仓库版本一致，再保存到 D 盘交付目录，视频不推入源码 Git。
