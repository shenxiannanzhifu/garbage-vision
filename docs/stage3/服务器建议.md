## 开机前实际准备

入口：scripts/prepare_remote_gpu.ps1。在Windows普通PowerShell运行，保持Docker Desktop与现有代理开启。

1. 要求stage3源码已提交且工作树干净，权重SHA256与官方记录一致，两张开发图存在，D盘可用空间至少40GiB。
2. 用独立的提交号标签构建Linux/amd64 CUDA12.8镜像，不覆盖现有CPU镜像标签。检查依赖和CUDA计算。
3. 在127.0.0.1:8082启动临时API，独立数据库与图片目录，仅运行两张本地模型图。收费上限强制0，不向容器传入模型服务商密钥；8080原项目保持运行。
4. 必须两图成功且设备确为cuda:0，才导出应用/nginx镜像、确定提交的源码、两个官方权重和两张样例，记录文件SHA256与镜像ID。包不含.env、私钥、原用户历史数据库。
5. 删除本次临时容器，保留预检证据与数据。输出在.local/remote-prep/<时间>/；成功包在其bundle/。此为本机私有部署包，不推Git，不冒充最终交付包。

GPU依赖首次下载可能较大；本机耗时不计云费。完成后查看实际压缩包大小，再估算上传耗时，不能假定大镜像立即传完。后续按实际网络决定上传预制镜像或在服务器构建，明确记录来源与复用缓存范围。

scripts/deploy_prebuilt.sh为后续服务器入口：校验部署包、导入镜像并核对ID/源码标签，在新目录解包、生成独立访问凭据、保持收费上限0、启动绑定回环8080的GPU Compose。要求服务器已有Docker/Compose和NVIDIA容器运行时，发现缺项即失败，不盲装或覆盖原数据。服务启动后仍必须完成远端真实图片、网页、持久化、双侧调用与视频验收。
